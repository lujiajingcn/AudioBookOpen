# AudioBookOrganizer

把计算机类专业书改成**能听的版本**：删掉代码清单、命令输出、参数表格、插图、目录页，
在原位置补一句「这里原本有什么」的口语说明，让它读起来还是一本连贯的书。

产出 `《原书名_精简有声化》.epub` + `.txt`，可直接进书城或喂给合成管线。

纯 Python 标准库，**不需要 pip install 任何东西**，不需要联网，不需要大模型。

---

## 快速开始

```bash
cd AudioBookOrganizer

# 单本
python organize.py "G:\学习\03-Linux与系统编程\Linux命令行大全.epub"

# 一批（目录下所有 epub）
python organize.py "G:\学习\03-Linux与系统编程" -o out

# 先看看会删掉多少，不出文件
python organize.py 某书.epub --mode audit

# 只删不补（想看「纯净版」原文长什么样）
python organize.py 某书.epub --mode strip
```

默认输出到 `./output/`。产物文件名固定为 `原书名_精简有声化.epub / .txt`。

### 参数

| 参数 | 说明 |
|---|---|
| `-o, --outdir` | 输出目录，默认 `./output` |
| `--mode rewrite` | **默认**。删掉不合适的，补上口语说明 |
| `--mode strip` | 只删不补，用于对比 |
| `--mode audit` | 只统计，不改文件 |
| `--format epub,txt` | 输出格式，可只留一种 |
| `--merge-threshold N` | 连续 N 处同类示例后开始合并成一句，默认 2，`0` 关闭 |
| `--no-transition` | 不加每章末尾的「下一章……」 |
| `--no-front-note` | 不加卷首的「这是有声化精简版」说明 |
| `--json-report 路径` | 统计写成 JSON |

## 处理规则

### 删（念出来是噪音）

| 内容 | 判定依据 | 处理 |
|---|---|---|
| 版权页 / 作者简介 / 索引 / 符号表 | 章节标题关键词 | 整节删除 |
| 纯目录页 | 整页只有 `toc` 类条目的链接 | **整页删除**，同步从 manifest / spine / NCX 剪掉 |
| 页眉页脚、「第 12 页」 | 文本形态 | 删除 |
| 装饰线、纯符号行 | 文本形态 | 删除 |
| 网址、脚注角标 `[12]` | 正则 | 删除，保留链接文字 |
| 提示框的图标文字（"提示""注意"） | 整段只有标签词 | 删除（内容若在别处会保留） |

### 改写（保留信息，去掉形态）

| 内容 | 改写方式 | 例子 |
|---|---|---|
| 命令会话 `[me@host ~]$ ls -l` | 抽出实际执行的命令 | 「接下来演示了 ls 命令，它用来列出目录内容。」 |
| shell / Python 脚本 | 行数 + 语言 + 结构 | 「紧接着是一段 50 行的 bash 脚本，主体是一个 while 循环。」 |
| 语法模板 `type <em>command</em>` | 只说是语法格式 | 「书中给出了 type 命令的语法格式。」 |
| 表格（两列术语表） | **整张念出来**（≤240 字），长了念前 3 条 | 「接着是表4-1《通配符》，一共 5 行，对照了通配符和匹配项：\*，匹配任意多个字符；……」 |
| 表格（多列参数矩阵） | 只报行列数和主题 | 「4 行 6 列，列出的是选项、含义……这种参数矩阵念出来没有意义，跳过。」 |
| 插图 | 用图题代替画面 | 「这里配了一张插图，标题是：图4-1 通配符示例。」 |
| ASCII 示意图 | 一句带过 | 「这里有一张用字符拼出的示意图，略过。」 |

### 补（让上下文不断裂）

- **卷首说明**：这是《X》的有声化精简版，代码图表已改写，细节请看原书。
- **衔接语自适应**：前一段是「实例如下所示。」，替代句就不再顶着「接下来」；
  否则五个开头词轮换（接下来 / 这里 / 紧接着 / 下面 / 此处），避免 949 个代码块同一句式。
- **同类合并**：连着好几处「这里有一张表」会变成噪音，超过阈值自动并成一句。
- **步骤化**：`1．取案板。` `2．取刀。` 连续 ≥3 条 → `第一步，取案板。` `第二步，取刀。`
- **章末过渡**：「这一章就到这里。接下来是第30章 故障诊断。」
- **列表拆行**：`<ul>` 整块塞一段会让 TTS 一口气念七条，拆成一条一段。

### 保留（一字不改）

正文段落、标题层级、术语解释、有信息量的提示框、作者的行文。**正文不做摘要**——
规则读不出「这段在讲什么」，硬编就会出错，所以宁可不删。

## 对示例书的实测

`Linux命令行大全.epub`（人民邮电出版社，Epubor 转码，38 个 XHTML）：

| 指标 | 结果 |
|---|---|
| 原字数 | 361,677 |
| 保留字数 | 223,470（62%） |
| 代码块 | 949 处 / 134,600 字 → 全部转为一行说明 |
| 表格 | 113 处（术语表整张念，矩阵跳过） |
| 插图 | 7 处 → 用图题代替 |
| 整页删除 | 1 页（目录页） |
| XHTML 合法性 | 37/37 well-formed |
| EPUB 一致性 | spine 无缺失、manifest 无悬空、NCX 457 个 navPoint 无死链、mimetype 首项且不压缩 |

## 代码结构

```
organize.py                 入口
audiobook_organizer/
  htmltree.py               极简 XHTML 树（解析 / 序列化，容错不闭合标签）
  classify.py               块分类：标题 / 段落 / 代码 / 表格 / 图 / 提示 / 目录条目
  codecut.py                代码块分析与概述（会话 / 脚本 / 语法 / 输出 / 示意图）
  tabulate.py               表格分类与概述（术语表 / 列表 / 矩阵）
  prose.py                  正文清洗、步骤化、插图概述、章间衔接
  phrasing.py               措辞库：命令用途词表、语言/结构识别、开头词轮换
  epub.py                   EPUB 读写（OPF / spine / NCX 剪枝、mimetype 规范）
  pipeline.py               主编排 + 压缩 + TXT 输出
  cli.py                    命令行
tests/test_organizer.py     33 个用例，python -m unittest discover -s tests
```

## 设计取舍

**为什么不用大模型？** 现在这版是规则版：不联网、零成本、结果可预期、949 个代码块
也是一秒出完。规则能读出来的只有「代码里有 while」「执行了 ls」「表头是通配符和匹配项」这种
**能被原文验证的事实**，读不出来的就不说——宁可少说，不许编。

想升级成 LLM 改写，替换点只有一处：`codecut.summarize` / `tabulate.summarize` /
`prose.image_summary` 三个函数，输入已经是结构化的 `CodeInfo` / `TableInfo`，
接一个 OpenAI 兼容接口把 `info.raw` 连同上下文交给模型重写即可，其余管线不动。

**为什么表格不一刀切删掉？** 两列的「命令 → 说明」对照表是这类书里知识密度最高的部分，
念出来完全成立（实测表 4-1 通配符念得挺好）。真正该跳的是多列参数矩阵。

**为什么按 h1 切「节」而不是按文件？** 同一本 EPUB 常把一个文件塞进版权页 + 作者简介 +
前言五个 h1（本书 `text00001.html` 就是），按文件删会把前言一起删掉。

## 已知局限

- 只处理 EPUB，TXT/PDF/MOBI 没做（MOBI 需要先转 EPUB）。
- 行内代码（正文里的 `cp -u *.html`）原样保留，TTS 会念成"cp 减 u 星号点 html"；
  嫌吵可以后续加行内代码替换开关。
- 英文注释不朗读，只引用中文注释；脚本名/专有名词按原样念。
- EPUB 3 的 `nav.xhtml` 做得比较粗（不剪枝），EPUB 2 的 NCX 是完整的。
- 边栏小标题（如「字符范围。」）会被当成普通短段落保留。
